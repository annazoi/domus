2. HIGH-LEVEL AUTH MODEL
================================================================================

Session model:
- There is NO server-issued access token in the active implementation.
- After sign-in or sign-up, the API returns user profile fields (id, email, names).
- The client stores `user_uuid` (same as database User.id) in a persisted Zustand store.
- An Axios request interceptor attaches `x-user-id: <user_uuid>` to every API call.
- API route handlers read that header to identify the current user.
- Logout clears Zustand state, removes the persist key from localStorage, and
  redirects to `/auth/sign-in`.

Important security note (document in code comments if needed):
- `x-user-id` is client-controlled and is NOT cryptographically verified.
- This pattern assumes a trusted first-party SPA context, not a public API.
- Do NOT present this as production-grade API security against malicious clients.
- Implement exactly as specified; do not "improve" it to JWT sessions unless asked.

No Next.js middleware:
- Do NOT add middleware.ts for auth gating.
- Protected pages rely on client state + API 401 responses.
- Dashboard is accessible without server redirect; API calls fail if not authenticated.

Legacy token hooks (include but keep commented out):
- Store fields: access_token, expires_in (commented out in Zustand)
- Axios interceptor: Bearer Authorization header (commented out)
- Token expiry check via isTokenExpired helper (commented out)
- API responses still return access_token: null, expires_in: null for compatibility

5. PASSWORD UTILITIES
================================================================================

File: app/api/_utils/password.ts

Use JWT to encode the plaintext password in the stored value:

const PASSWORD_PAYLOAD_KEY = 'password';

function getJwtSecret(): string {
  const secret = environments.JWT_SECRET;
  if (!secret) throw new Error('JWT_SECRET is not configured');
  return secret;
}

export function hashPassword(password: string): string {
  return jwt.sign({ [PASSWORD_PAYLOAD_KEY]: password }, getJwtSecret());
}

export function isHashedPassword(storedPassword: string): boolean {
  return storedPassword.startsWith('eyJ');  // JWT header prefix
}

export function verifyPassword(password: string, storedPassword: string): boolean {
  if (isHashedPassword(storedPassword)) {
    try {
      const decoded = jwt.verify(storedPassword, getJwtSecret()) as Record<string, string>;
      return decoded[PASSWORD_PAYLOAD_KEY] === password;
    } catch {
      return false;
    }
  }
  // Legacy plaintext fallback for migration
  return storedPassword === password;
}

File: app/api/_utils/guest-account.ts

export function isGuestAccount(password: string): boolean {
  return password === '';
}

6. AUTH REQUEST UTILITIES

File: app/api/_utils/auth.ts

/** Authenticated user id (host or guest), from `x-user-id` header. */
export const getUserIdFromRequest = (request: Request): string | null => {
  const id = request.headers.get('x-user-id');
  if (!id) return null;
  return id;
};

export const getHostIdFromRequest = getUserIdFromRequest;  // alias

Usage in every protected route handler:
  const userId = getUserIdFromRequest(request);
  if (!userId) return Response.json({ message: 'Unauthorized' }, { status: 401 });

For resource ownership:
  if (id !== userId) return Response.json({ message: 'Forbidden' }, { status: 403 });

Optionally verify user still exists:
  const user = await prisma.user.findUnique({ where: { id: userId }, select: { id: true } });
  if (!user) return Response.json({ message: 'Invalid host session. Please sign in again.' }, { status: 401 });

8. API ROUTES: SIGN-IN
================================================================================

Route: POST /api/auth/sign-in
File: app/api/auth/sign-in/route.ts

Request body:
  { email?: string; password?: string }

Validation:
  - email and password required → 400
  - email trimmed, lowercased
  - basic email regex: /\S+@\S+\.\S+/

Logic:
  1. findUnique user by email (select id, email, first_name, last_name, vat_number, password)
  2. Reject if: no user, isGuestAccount(password), or !verifyPassword(input, stored)
     → 401 { message: 'Invalid credentials. Please try again.' }
  3. On success, update user:
     - is_archived: false
     - if password is NOT hashed yet, upgrade: password: hashPassword(input)
  4. Return 200 JSON:

{
  id: user.id,
  user_uuid: user.id,
  uuid: user.id,
  email: user.email,
  first_name: user.first_name,
  last_name: user.last_name,
  access_token: null,
}

Errors:
  - 500 generic: 'Could not sign in. Please try again.'
  - Never leak whether email exists vs wrong password (same 401 message)

9. API ROUTES: SIGN-UP
================================================================================

Route: POST /api/auth/sign-up
File: app/api/auth/sign-up/route.ts

Request body:
  { first_name?, last_name?, email?, password? }

Validation:
  - first_name and last_name required (trimmed) → 400
  - email and password required → 400
  - email format valid → 400
  - password min length 8 → 400

Logic:
  1. Check existing user by email
  2. If exists AND NOT guest account → 409 'User already exists with this email.'
  3. If exists AND IS guest account → UPDATE user with names, host_name, hashed password, is_archived: false
  4. If not exists → CREATE user with same fields
  5. Return 201 JSON (same shape as sign-in + created_at)

Errors:
  - 500: 'Could not create account. Please try again.'

13. ZUSTAND AUTH STORE
================================================================================

File: store/auth.ts

import { create } from 'zustand';
import { devtools, persist } from 'zustand/middleware';

const STORE_KEY = 'auth';

interface UserStore extends LoggedInUser {
  login(user: LoggedInUser): void;
  logout(): void;
  updateUser(user: Partial<LoggedInUser>): void;
}

export const useAuthStore = create<UserStore>()(
  devtools(
    persist(
      (set) => ({
        isLoggedIn: false,
        user_uuid: null,
        first_name: null,
        last_name: null,
        email: null,

        login: (user) => {
          set((state) => ({
            ...state,
            user_uuid: user.user_uuid,
            email: user.email,
            first_name: user.first_name,
            last_name: user.last_name,
            isLoggedIn: true,
          }));
        },

        logout: () => {
          set((state) => ({
            ...state,
            isLoggedIn: false,
            user_uuid: null,
            first_name: null,
            last_name: null,
            email: null,
          }));
          localStorage.removeItem(STORE_KEY);
          window.location.href = '/auth/sign-in';
        },

        updateUser: (user) => {
          set((state) => ({ ...state, ...user }));
        },
      }),
      { name: STORE_KEY },
    ),
  ),
);

export const getAuthStoreState = () => useAuthStore.getState();

Hydration helper (required for SSR/persist race conditions):

export const useAuthHydrated = () => {
  const [hydrated, setHydrated] = useState(() => {
    if (typeof window === 'undefined') return false;
    return useAuthStore.persist?.hasHydrated() ?? false;
  });

  useEffect(() => {
    if (hydrated) return;
    const persist = useAuthStore.persist;
    if (!persist) { setHydrated(true); return; }
    if (persist.hasHydrated()) { setHydrated(true); return; }
    return persist.onFinishHydration(() => setHydrated(true));
  }, [hydrated]);

  return hydrated;
};

TanStack Query hooks that depend on auth must use:
  enabled: hydrated && Boolean(userId)

20. ERROR RESPONSE CONVENTIONS
================================================================================

All API errors return JSON: { message: string }

Status codes:
  400 — validation errors (specific message)
  401 — missing x-user-id or invalid credentials
  403 — authenticated but not allowed (wrong resource owner)
  404 — resource not found
  409 — duplicate email, duplicate host name
  500 — generic server error (no stack traces to client)

Sign-in/sign-up catch blocks return generic 500 messages; do not expose internals.
